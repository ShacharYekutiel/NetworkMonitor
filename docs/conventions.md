# NetworkMonitor — Conventions

## General
- The contract lives in `docs/`, and you change the docs **before** or **together with** the code. If you find
  the contract wrong while implementing, report it to the architect instead of diverging silently.
- Language: code, comments, logs, API `message` strings and commits are in English. User-facing text belongs only
  in the frontend locale files (`en.json`, `he.json`) and in the backend notification templates (en/he).
- Commits: imperative mood, `area: summary` (e.g. `poller: add snmp_interface counter wrap handling`).

## Backend (Python, `backend/`)
- Python 3.12+. Formatting and linting with **ruff** (`ruff format`, `ruff check`), line length 100. Type hints
  everywhere. `mypy --strict netmon` should pass for new modules (it is not CI-blocking in Phase 1).
- Async only on request and poller paths. Never call blocking I/O on the loop. Use `asyncio.to_thread` for
  unavoidable sync code.
- Layering:
  - `api/` routers are thin. They validate through `schemas/`, then call `services/`.
  - The ORM lives in `models/`.
  - Pydantic models in `schemas/` mirror [api.md](api.md) one to one, with the same field names.
- DB access: SQLAlchemy 2 async sessions, one session per request (a dependency) and one short session per poll
  result. Raw SQL is allowed for the time-series queries (`services/history.py`).
- Migrations: Alembic (`backend/netmon/migrations`), plain PostgreSQL DDL only. Timescale calls belong only in
  `db/timescale.py`.
- Errors: raise `netmon.api.errors.ApiError(status, code, message, details=None)`. The global handlers render the
  [error envelope](api.md#error-format), including for `RequestValidationError` and `HTTPException`.
- Logging: the stdlib `logging` module with a `netmon.<module>` logger. Never log secrets (community strings, keys,
  passwords, the JWT).
- Sensor plugins: `netmon/poller/checks/<type>.py` exposes `async def run(ctx: CheckContext) -> CheckResult`.
  A plugin never raises for an expected failure. It returns `ok=False` with a message.
- Tests: pytest + pytest-asyncio + httpx `AsyncClient` (ASGI transport), under `backend/tests/`.
  - Tests that need the DB use `TEST_DATABASE_URL`, and are skipped if it is unset.
  - Each test session creates a fresh database `netmon_test_<random>`.
  - CI runs the suite twice: against `timescale/timescaledb:latest-pg16`, and against `postgres:16`, which
    covers fallback mode. On a Timescale server, `NETMON_DISABLE_TIMESCALE=1` forces fallback mode for the
    whole run. Independently of that, the suite always creates a second database (`netmon_test_<random>_fb`)
    that runs in fallback mode, so one run covers migrations, history and retention in both modes.
  - SNMP tests start a real `snmpsim-command-responder` (dev extra: `snmpsim` + `pysmi`) on a free UDP port
    with `.snmprec` data generated by the test. They are skipped if snmpsim is missing. When the tests run
    as root, the agent drops privileges to `nobody:nogroup`.
  - Network checks are tested against local fakes: an aiohttp/httpx test server, a local TCP listener, a dnslib
    fake, and snmpsim from `tests/sim/`.

```bash
cd backend
python -m venv .venv && . .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -e ".[dev]"
ruff format --check . && ruff check .
TEST_DATABASE_URL=postgresql://netmon:netmon@localhost:5432/postgres pytest -q
```

## Frontend (TypeScript, `frontend/`)
- React 18 + TypeScript `strict`, Vite, Tailwind CSS, React Router, TanStack Query, ECharts, i18next.
  Use ESLint + Prettier (2 spaces, single quotes, trailing commas).
- API layer:
  - `src/api/types.ts` is a hand-written mirror of the [api.md](api.md) types.
  - `src/api/client.ts` wraps `fetch`: relative `/api` URLs, `credentials: 'same-origin'`, and the JSON header.
    It throws `ApiError {status, code, message, details}` parsed from the error envelope.
  - `src/api/ws.ts` is a single shared WebSocket connection. It handles reconnect, and `config.changed` /
    `event.created` invalidate TanStack queries.
- i18n:
  - Every visible string goes through `t()`. Keys are dotted (`devices.addTitle`).
  - Error codes map to `errors.<code>`, channels to `channel.<key>`, sensor types to `sensorType.<type>`,
    statuses to `status.<status>`.
  - `he` sets `<html dir="rtl" lang="he">`, and `en` sets `dir="ltr"`.
- RTL:
  - Use only logical utilities/properties (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`,
    `text-start`), never `ml-/mr-/left-/right-`. Directional icons flip with `rtl:rotate-180`.
  - Numbers, IPs and hostnames are wrapped in `<bdi>` / `dir="ltr"` spans.
  - ECharts time axes stay left-to-right in both languages.
- Visual design: follow `docs/design-system/` (rules in its `README.md`, values in `tokens.json`, rollout in
  `IMPLEMENTATION.md`). Colours, fonts and radii come only from the design tokens — no hard-coded Tailwind palette
  classes. Status colours are the `status-*` tokens (up, warning, down, unreachable, unknown, paused).
- Language choice: use the logged-in `user.language`. Before login, use `localStorage['netmon.lang']`, then
  `GET /api/settings/public`'s `default_language`.
- Tests: Vitest + Testing Library, colocated as `*.test.tsx`. `npm run build` must finish with **zero** TS errors.

```bash
cd frontend
npm install
npm run lint && npm test -- --run && npm run build      # build → frontend/dist
```

## Local development

1. Start a database (TimescaleDB, on port 5432, user/password/db `netmon`/`netmon`/`netmon`):
   ```bash
   docker compose -f deploy/docker-compose.dev.yml up -d
   ```
   Plain PostgreSQL ≥ 14 with the same credentials works too, in fallback mode.
2. Start the backend on port 8080, with auto-reload:
   ```bash
   cd backend && . .venv/bin/activate
   export DATABASE_URL=postgresql://netmon:netmon@localhost:5432/netmon NETMON_DATA_DIR=../.devdata NETMON_DEV=1
   netmon serve            # runs migrations, then serves http://localhost:8080
   ```
3. Start the frontend dev server on port 5173. `vite.config.ts` proxies the API and the WebSocket to the
   backend:
   ```ts
   server: { port: 5173, proxy: {
     '/api': { target: 'http://localhost:8080', changeOrigin: false },
     '/ws':  { target: 'ws://localhost:8080', ws: true },
   } }
   ```
   ```bash
   cd frontend && npm run dev   # open http://localhost:5173
   ```
   Keep `changeOrigin: false`. The proxy then forwards the browser's `Host`, so it matches `Origin`, and the CSRF
   origin check passes.
4. Full production-like run: `cd frontend && npm run build`, then `netmon serve` serves the SPA from
   `frontend/dist` at http://localhost:8080.

## E2E / integration (QA, `tests/`)
- `tests/e2e`: Playwright, with `BASE_URL` defaulting to `http://localhost:8080`. Run with
  `npx playwright test`.
- `tests/integration`: pytest against a running instance (`BASE_URL`, `DATABASE_URL`).
- `tests/sim`: snmpsim recordings (`.snmprec`) and helper targets (HTTP, TCP, DNS).

## Definition of done (per change)
Lint is clean and the tests pass. The contract docs are updated if the behaviour changed. The change works in
both Timescale mode and fallback mode, and on Windows paths (no POSIX-only calls without a fallback).

  running for it. Tests cover OFF, ON and ON → OFF → ON for each feature.
- Keep pure and exhaustively unit-tested: `netmon.ingest.syslog_parse`, `trap_decode`, `oid_names`, `rules`,

## Phase 3b notes
- Every 3b feature follows the 2b-3 toggle rules (OFF by default, runtime start/stop, `409 feature_disabled`, OFF
  leaves no task, queue, poll handler or credential in memory). Tests cover OFF, ON and ON → OFF → ON for each of the
  11 features, and the idle state (ON with a missing dependency).
- **Configure-first UX rule** (owner; applies to `assistant` and `ai_knowledge`, and to any future feature that needs
  configuration before it can work): the settings form is always shown; the enable switch sits at the **bottom** of
  the form next to *Test connection*; it is locked until a test of the **current form values** succeeded in the current
  page session; the server enforces it with a `test_id` bound to the user and the hash of the connection fields.
- **The model never changes anything.** Never add a tool that writes, sends, acknowledges, runs a command or SQL, or
  reads a secret. A new tool needs: an args model with `extra="forbid"`, a feature gate, a pure `project_*` function
  listing every field explicitly, caps, `ref`s, an entry in api.md § [3b] Tools, and a projection test with seeded
  secret markers. Tool handlers use a read-only transaction (`SET TRANSACTION READ ONLY`) and `statement_timeout`.
  Drafts are returned, never saved; saving goes through the normal endpoints.
- Every string that leaves for Bedrock passes `netmon.assistant.redact.apply()`; never build a prompt from raw rows.
  Tool results go back as Converse `json` blocks, never concatenated into prompt text.
- Keep pure and exhaustively unit-tested: `netmon.assistant.sigv4`, `eventstream`, `redact`, `prompt`, `context`,
  `links`, `pricing`, `usage` cap arithmetic, `bedrock.map_error`, `features.correlate.cluster`,
  `features.diffexplain.risk_flags`, `features.digest.signature`/`compare`, `features.templates.compact_walk`,
  `detect_language`. I/O lives in `credentials`, `bedrock`, the agent, the tools and the feature runners.
- **No new runtime dependency:** Bedrock is called with httpx (`trust_env` per `proxy_mode`,
  `verify=tlsutil.httpx_verify(True)`) and our own SigV4; `cryptography` signs Roles Anywhere requests. `botocore` is a
  **dev/test-only** dependency (signature cross-check in the mock). Never import boto3/botocore from `netmon/`.
- Never log AWS credentials, `Authorization`, `X-Amz-Security-Token`, `X-Amz-X509`, prompts, questions or answers
  (the audit log is the record); log only codes, sizes, durations and token counts.
- Connection layer (developer A) — use it, do not re-implement it: `rt.assistant.client` (`netmon.assistant.bedrock.
  BedrockClient`: `converse` / `converse_stream` / `converse_stream_collect` / `retrieve` / `list_models`;
  `StreamAssembler`), `rt.assistant.usage` (`netmon.assistant.usage.UsageService`: `check_and_reserve`, `check`,
  `record`, `record_error`, `background_allowed`), `netmon.assistant.gates.require_ai`, `netmon.assistant.errors.
  AssistantError` (`.to_api()`); settings objects via `netmon.assistant.config.load` / `load_kb` / `scalars`.
- Owner decisions after the contract: default region `us-east-1` + `us.` profile (`il-central-1` + `global.`
  supported, warning only); USD monthly cost cap; **no question text in the audit log** (title only); Roles
  Anywhere recommended with a server-side *Generate CSR* action; Knowledge Base implemented, OFF.
- Never hard-code a model id or a price; tests use `eu.anthropic.claude-test-v1:0` against the mock only. Never call
  real AWS in CI.
- AI output is rendered with the restricted Markdown renderer (frontend: `markdown-it` with `html: false`, images
  disabled, link validator allowing only server-issued `nm:` refs and KB source URLs; MIT licence, the only new
  frontend dependency). Every AI text carries the "AI-generated" label (i18n `assistant.aiGenerated`).
- Background AI work must never sit in the alert send path or the report compute path: enqueue after the send/compute,
  bounded queues, deadlines, skip on any error (counted, not raised).
- SSE endpoints: `StreamingResponse` with `text/event-stream`; the run lives in a background task registered in
  `rt.assistant.runs`; the HTTP disconnect does not cancel it; cancellation only through the cancel endpoint, delete,
  shutdown or feature OFF.
- Pydantic models (`extra="forbid"`): `AssistantSettingsIn`, `AssistantTestIn`, `AskIn`, `FeedbackIn`,
  `ConversationPatch`, `ExplainIn`, `DiffExplainIn`, `DigestRunIn`, `RuleDraftIn`, `WalkIn`, `TemplateDraftIn`,
  `UserTemplateIn`, `KnowledgeSettingsIn`, one args model per tool; alert-rule create/PATCH gain `ai_note`, report
  create/PATCH gain `ai_summary`, Telegram config gains `ai_ask`, email config gains `ai_note_email`.
- Frontend: extend `types.ts` / `endpoints.ts` / `ws.ts` exactly as api.md § Phase 3b; an `sse.ts` helper (fetch +
  ReadableStream parser, `Last-Event-ID` re-attach, abort) — not `EventSource`; answers use `dir="auto"` per block,
  IPs/MACs/OIDs/code `dir="ltr"`; the bottom switch component `ConfigureFirstSwitch` is shared by both
  configure-first forms.
- Existing test changes allowed in 3b (contract changes on purpose): `test_migrations.py` (head `0008`), feature lists
  (28 names), `AlertRule`/`Report`/`ReportRun`/`ReportData`/channel-config shape tests (new keys), audit `source`
  values, `test_audit` (turning `audit` OFF while `assistant` is ON is refused). Any other failing existing test is a
  regression.
